# PRD · 故事访谈 Agent（暂名 life-agent）

> 版本 v0.1 · 2026-07-27 · 状态：MVP 设计中

## 1. 一句话定位

**人人都有好故事，只是不会讲。** life-agent 是一个"采访者 + 导演" agent：通过访谈式对话把普通人讲不出来的故事挖出来，替他讲好，最终以图文/视频的形式引起共鸣。

## 2. 背景与洞察

- 大多数人的表达能力有限，但经历本身足够动人；"我很难过"没人有感，"我在楼道里站了十分钟才敢按门铃"才有共鸣。
- 焦虑的人向别人表达时常常语言不当、不被理解，但仍然希望自己的事情被记录、被懂、被同类听见。
- 共鸣的载体已经迁移到短视频平台（抖音 / B站 / 小红书），故事的最终形态应该顺应这个分发环境。

产品要解决的不是"写作工具"问题，而是三层递进的需求：

| 层 | 需求 | 产品答案 |
|---|---|---|
| 1 | 说出来 | 访谈式对话，用户只需回答小问题，零组织语言成本 |
| 2 | 被讲好 | agent 消化混乱素材，产出第一人称故事稿，用户只确认事实与感受 |
| 3 | 被共鸣 | 图文卡片 / 原声视频，用户自主发布到社交平台 |

## 3. 核心设计

### 3.1 访谈 agent（核心中的核心）

- 交互形式：语音为主、文字为辅的多轮对话；一次只问一个具体的小问题。
- 追细节原则：追原话（"他当时说了什么"）、追具象（"你手里拿着什么"）、追第一反应（"听到那句话的瞬间你想到什么"）。共鸣来自细节，不来自辞藻。
- 容错原则：语无伦次、方言、停顿、说一半都可以；素材的混乱由 agent 消化，叙事结构由 agent 搭建。
- 人格要求：倾听者，不评判、不说教、不急着安慰；先复述确认，再继续追问。

### 3.2 故事稿生成

- 结构模板化：铺垫 → 转折 → 情绪落点（故事弧线）。
- 产出第一人称故事稿回给用户："这是你的故事，我讲得对吗？"——用户修改的是事实和感受，不是文笔。
- aha moment：用户在首次使用的一次访谈内，看到一篇"让自己想转发"的故事稿。

### 3.3 呈现形态（分阶段）

1. **图文卡片**（MVP）：小红书式长图，成本≈0，先验证共鸣。
2. **原声视频**（第二阶段）：
   - 旁白用**用户访谈时的真实原声**剪辑——停顿、哽咽、笑场、方言正是最动人的部分；用户无需任何表演。
   - 画面轻量化：竖屏 + 逐句字幕 + AI 氛围插画 / 空镜 b-roll + 踩情绪节点的配乐。画面是氛围，声音才是故事。
   - 隐私降级选项：变声处理，或 AI 语音朗读故事稿。

### 3.4 分发与增长

- 用户把自己的故事视频发到自己的社交账号（带产品水印/入口），看到的人里就有"我也有故事想讲"的下一批用户——共鸣分发先借现有平台流量，不自建社区。
- 故事库攒起来之后，再做站内"听同类故事"的经历相似度匹配；回应动作只有"我也是"（无评论、无私信），保留共鸣、排除评判风险。

## 4. 底线（上线前提，非可选项）

1. **默认绝对私密**：所有内容默认仅用户与 agent 可见，发布是逐条显式授权的例外。
2. **危机兜底**：识别自伤/危机信号并转介专业求助资源（心理援助热线等）；明确产品不替代专业心理咨询。

## 5. MVP 范围

**只做单人闭环：访谈 → 故事稿 → 图文卡片。**

- ✅ 语音/文字访谈对话（追细节提示词体系）
- ✅ 故事稿生成与用户确认修改
- ✅ 图文卡片导出
- ❌ 视频管线（第二阶段）
- ❌ 共鸣匹配/社区（第三阶段）

**验证指标**：用户看到自己的故事稿时，是否主动想发给别人看；次周回访率。

## 6. 技术草案

- 对话层：LLM 多轮访谈（核心资产是提示词设计：采访者人格 + 追细节策略 + 故事弧线模板）
- 语音层：ASR 转写（保留原始音频供后续视频剪辑用）
- 记忆层：会话摘要 + 向量检索（跨会话记得用户提过的事）
- 生成层：故事稿 → 图文卡片渲染；后续接原声剪辑 + TTS + 图像生成

## 7. 路线图

| 阶段 | 内容 |
|---|---|
| P0（当前） | 访谈 agent 对话设计 + 故事稿生成，跑通"聊 20 分钟出一篇想转发的故事稿" |
| P1 | 图文卡片导出，小范围真人测试 |
| P2 | 原声视频管线 |
| P3 | 站内共鸣匹配 |
