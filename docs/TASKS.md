> 改变方向、砍需求、换方案时在这里记一行"为什么"，防止日后忘记当初的理由。

| 日期 | 决策 | 原因 |

| 2026-07-27 | MVP 只做单人闭环，视频和社区后置 | 先验证"被懂/想转发"是否成立，见 PRD §5 |

| 2026-07-27 | 语音输入用 push-to-talk（按住说话） | 绕开 VAD 静音阈值/轮次判断这个语音交互最难的问题，见 TECH §3.5.8 |
| 2026-07-27 | LLM 网关内置 MOCK 模式（无 key 返回固定文本） | 前后端联调不被 API Key 阻塞 |
| 2026-07-27 | 模型选 gpt-5.5（对话+故事稿同款），暂不用 gpt-5.6 | 用户的中转站实测 5.6 返回 Service temporarily unavailable；5.5 全链路验证通过（访谈复述+追问、状态抽取、故事稿零编造过审）。密钥走 backend/.env，不入库 |

## 使用规则

1. **每次开发会话开始**：读本文档「进行中」+ 当前里程碑，接着干。
2. **每次开发会话结束**：更新勾选状态，把完成项移入「已完成」表；有新发现的任务就近插入对应里程碑。
3. **任何方向/方案变更**：先记入「决策与变更日志」，再同步修改 PRD/TECH 对应章节。
4. 文档更新与代码同一个 commit 提交，保持一致。
5. 里程碑内按顺序做；跨里程碑并行要有理由（记入日志）。
